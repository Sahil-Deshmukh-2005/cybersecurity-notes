### HTTP Messages (Request/Response)
1. Start Line :  
This gives introduction about the message.

2. Header :  
Header is a set of Key:Value pairs, that gives extra information about the message.

3. Empty Line :  
After Header there is always a empty line.

4. Body :  
Body is where the actual data is stored.

***

### HTTP Headers for Request
1. Host :  
Ex, `Host: tryhackme.com`  
Specifies the name of the web server the request if for.  
  
2. User-Agent :  
Ex, `User-Agent: Mozilla/5.0`  
Shares information about the web browser the request is coming from.  
  
3. Referer :  
Ex, `Referer: http://www.google.com/`  
Indicates the URL from which the request came from.  
  
4. Cookie :  
Ex, `Cookie: user_type=student;room=introtowebapplication;room_status=in_progress`  
Information the web server previously asked the web browser to store is held in cookies.  
  
5. Content-Type :  
Ex, `Content-Type: application/json`  
Describes what type or format of data is in the request.  

***

### HTTP Headers for Response
1. Date :  
Ex, `Date: Fri, 23 Aug 2024 10:43:21 GMT`  
Shows exact date and time when the response was generated by the server.  
  
2. Content-Type :  
Ex, `Content-Type: text/html; charset=utf-8`  
It tells the client what type of content it's getting.  
  
3. Server :  
Ex, `Server: nginx`  
Shows what kind of server software is handling the request.  
  
4. Set-Cookie :  
Ex, `Set-Cookie: sessionId=165asa41cd5`  
This one sends cookies from the server to the client, which the client then stores and sends back with future requests.To keep things secure, make sure cookies are set with the `HttpOnly` flag (so that they cannot be accessed by JavaScript) and the `Secure` flag (so that they're sent over HTTPS)  
  
5. Cookie-Control :  
Ex, `Cookie-Control: max-age=600`  
Tells the client how long it can cache the response before checking with the server again. It can also prevent sensitive info from being cached if needed (using `no-cache`).  
  
6. Location :  
Ex, `Location: /index.html`  
This is used in redirection (3xx) responses. It tells client where to go next if the resource has moved.

### Security Headers 
HTTP Security Header help improve security of the web application by providing mitigations against the attacks like Cross-Site Scripting (XSS), clickjacking, and others.   
  
1. Content-Security-Policy (CSP) :  
This gives additional security against attacks like XSS. It provides a way for administrators to say what domains or sources are considered safe and provides a layer of mitigation to such attacks.  
Ex, `Content-Security-Policy: default-src 'self'; script-src 'self' http://cdn.tryhackme.com; style-src 'self'`  
    - default-src : it means only current website.
    - script-src : it specifics the policy for where the script can be loaded from, which is self along with script hosted on https://cdn.tryhackme.com
    - style-src : it specifics the policy for where style CSS style sheets can be loaded from the current website (self).
  
2. Strict-Transport-Security (HSTS) :  
The HSTS Header ensures that web browsers will always connect over HTTPS.  
Ex, `Strict-Transport-Security: max-age=630511200; includeSubDomains; preload`  
    - max-age : This is expiry time in seconds.
    - includeSubDomains : An optional setting that instructs the browser to apply this setting to all subdomains.
    - preload : This allows the website to be include in preload lists. Browsers can use preload lists to enforce HSTS before even having their first visit to a website.
  
3. X-Content-Type-Options :  
It can be used to instruct browsers not to guess the MIME type of a resource but only use the Content-Type header.  
Ex, `X-Content-Type-Options: nosniff`  
    - nosniff : This directive instructs the browser not to sniff or guess the MIME type.
